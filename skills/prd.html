WORKHUB STUDIO / PRODUCT REQUIREMENTS

平台 Skills 统一分发

平台维护一次，租户直接使用；Agent 自主选择升级时机。

产品需求文档 v1.02026-11-11依据已确认原型整理

01背景与目标

当前，各租户需要先获取 Skill ZIP 包、上传至自己的空间，再为 Agent 绑定使用。官方通用 Skill 也采用这一方式，租户需要线下索取文件，平台更新技能后还需重复通知和上传，容易出现维护重复、版本不一致的问题。

本次新增平台 Skills 统一管理与分发能力。超级管理员负责维护官方技能及版本，按需要向全部或指定租户提供；租户无需下载、上传技能包，即可查看并为 Agent 绑定。

核心原则：租户技能列表展示平台最新发布版本，Agent 保持已绑定版本。平台发布更新，不自动改变已有 Agent 的使用行为。

本期范围

  • 超管创建、编辑、分类管理、上传与发布版本、设置分发范围及删除平台 Skill。
  • 租户区分“平台提供”和“空间自建”两类技能；平台技能只读。
  • Agent 直接绑定可用技能，查看当前版本并手动升级。
  • 分发范围调整、版本发布与平台删除对租户及既有绑定的影响。

不包含：将既有空间自建 Skill 自动转换为平台 Skill、自动替换 Agent 原有绑定、跨 Agent 批量升级、版本回滚与分发审批流程。空间自建技能的原有管理能力继续保留。

02用户使用流程

平台准备技能创建技能，上传 ZIP 包并发布版本。
→
平台确定范围向全部租户或指定租户分发。
→
租户查看与使用在平台提供中查看，直接为 Agent 绑定。
→
按需升级平台发布新版，Agent 配置者确认后升级。

分发范围可以先于首个版本发布设置。只有技能已有发布版本，且当前租户处于分发范围内，租户才会看到该平台技能。

典型场景

平台将“POPO 文档”v1.0 分发给全部租户。EHR 的员工服务助手直接绑定 v1.0，无需上传 ZIP。平台随后发布 v1.1，EHR 的“平台提供”列表展示 v1.1，但员工服务助手继续使用 v1.0；配置者查看更新说明并确认升级后，该 Agent 才切换至 v1.1。

03平台技能管理

超级管理员从“平台管理 → 能力管理 → Skills”进入，Skills 位于 MCP 上方。

3.1 建立与维护技能

超管先创建一个可持续维护的技能条目，再为其上传版本。创建成功不等于已向租户提供；未发布版本的技能仅供平台侧维护。

信息填写及使用规则
技能名称必填，位于首项，用于超管、租户及 Agent 配置中的识别。
技能标识第二项，选填；留空时系统生成。手工填写需符合标识规则，并在平台技能中保持唯一；创建后不修改，避免技能身份变化。
描述选填，说明技能能解决的问题及适用场景。
状态必选，启用 / 停用，默认启用；超管可修改，租户同步查看。停用对调用及绑定的具体影响见第 10 节。
分类选填，选择平台已维护的分类；不选择时归为未分类。
图标列表独立展示，用于识别技能；没有自定义图标时展示默认图标。

平台创建表单不要求填写开发者及展示标签。技能名称、描述等信息由平台统一维护，修改后租户查看到更新后的信息；基本信息变化不会替换 Agent 绑定的技能包版本。

3.2 平台列表中的信息

超管可查看：图标、技能名称、描述、版本、分类、状态、分发范围、创建人 / 创建时间、更新人 / 更新时间、操作。技能名称下可展示标识，便于区分相近名称。

  • “版本”指当前最新发布版本；尚无发布版本时显示待发布，有未发布的新包时可识别其待发布状态。
  • 创建人和创建时间保留首次创建记录；编辑、上传、发布、调整分发或关联分类变更后，更新人和更新时间随之更新。
  • 支持按名称或标识搜索，并按分类、分发范围筛选。
  • 列表提供查看、上传版本、分发、删除；技能基本信息在详情中维护。

3.3 管理分类

超管可增加分类、修改名称和标识颜色、删除分类。分类名称不能为空且不能重复。修改分类名称后，关联平台技能同步使用新名称；删除分类后，关联技能成为“未分类”，技能本身、分发范围和 Agent 绑定均保留。平台分类管理不改变空间自建分类。

3.4 上传与发布版本

  1. 上传：为已有技能提交 ZIP 包、版本号和更新说明。技能包需包含 SKILL.md；不合规包不能作为可用版本发布。同一技能不能重复使用已有版本号。
  2. 待发布：上传成功后保存为待发布版本，供超管确认。此时租户仍看到之前的最新发布版本，已有 Agent 不受影响。
  3. 发布：超管确认后，新版本成为该技能的最新发布版本；分发范围内的租户同步看到该版本。
  4. 保留历史：已发布版本保留，供版本查阅及已有 Agent 继续使用。新增发布不覆盖历史版本的内容。

技能详情提供技能内容、版本历史和 Manifest。分发范围统一在平台列表中管理，详情不重复设置分发入口。

3.5 删除平台技能

删除前明确告知当前分发及绑定影响。超管确认删除后，该 Skill 从平台列表及所有租户的“平台提供”中移除，禁止新增绑定。

已有 Agent 继续使用原绑定版本，可查看当前绑定内容、解绑，但不能升级。解绑后不能重新绑定该已删除技能。删除技能条目不代表同时销毁已有绑定所需的历史版本。

04分发与可见范围

分发方式租户获得技能的规则
全部租户当前所有租户及未来新增租户均在分发范围内，无需逐个添加。
指定租户仅选中的租户在范围内；支持搜索租户后选择多个目标。没有选中租户时，技能处于未分发状态。

范围保存后，新增目标租户可查看并绑定技能的最新发布版本；移出范围的租户不再看到该 Skill，也不能新增绑定。范围变更不主动解绑或替换任何 Agent 的已有版本。

  • “全部租户”改为“指定租户”：未选中的租户失去该技能的新增获取资格。
  • 取消全部指定租户：停止对所有租户新增分发。
  • 再次分发给被移出的租户：技能重新出现在其平台列表，新绑定使用最新发布版本；历史绑定仍保持原版本，可按需升级。
  • 租户不能通过自行上传平台更新包来修改官方技能；自行上传的技能属于空间自建来源。

05租户技能管理

租户 Skills 分为“平台提供”和“空间自建”，让用户明确技能由谁维护、是否需要自己更新。

来源内容范围租户可做什么
平台提供平台已发布且分发给当前租户的技能。查看技能信息、内容、已发布版本历史及 Manifest；直接在 Agent 中绑定。不允许修改、删除或上传版本。
空间自建由本空间自行创建和维护的技能。沿用已有创建、编辑、上传和删除权限。列表操作统一为查看，维护操作在详情中进行。

两个列表字段统一为：图标、技能名称、描述、版本、分类、状态、更新时间、操作。操作列仅提供“查看”；可按名称或标识搜索、按分类筛选。

平台技能的版本、状态、基本信息及更新时间随平台维护结果同步，租户不需要重复上传。租户只能查看已发布版本，平台侧待发布内容不作为租户可用版本。

“平台提供”为空时，应让用户知道当前空间暂无平台已分发技能。平台条目被移除不影响“空间自建”中的同名技能，两类来源及 Agent 绑定分别管理。

06Agent 绑定与升级

6.1 为 Agent 选择技能

具备 Agent 配置权限的用户在“配置 → Skill”中，通过“可用”和“已绑定”两组技能管理当前 Agent 的能力。

  • 可用：展示当前租户可获取、已有发布版本、且当前 Agent 尚未绑定的技能，涵盖平台提供和空间自建。用户可以识别技能来源及可绑定版本。
  • 已绑定：展示当前 Agent 实际绑定的技能及固定版本，包括已停止分发或被平台删除但仍有历史绑定的技能。
  • 两组分别搜索，互不影响；数量表示各组技能总数。同一 Agent 不重复绑定同一技能。

用户选择单个技能即可绑定；“全选”绑定当前可用搜索结果中的全部技能。绑定成功后技能从可用组移到已绑定组，并固定为绑定时的最新发布版本。

6.2 手动升级

平台发布新版本后，已有绑定不变。对仍在分发范围内且有新版的技能，用户可查看当前版本、目标版本及更新说明，再确认升级。

升级只影响当前 Agent；其他 Agent 即使绑定相同技能，也保持各自版本。升级后的后续执行使用新版本，不把已执行的历史任务改为新版结果。

6.3 解绑与清空

解绑后，当前 Agent 不再使用该技能。如果技能仍可获取，会重新出现在可用组；重新绑定使用当时的最新发布版本。

“清空”表示解除当前 Agent 的全部绑定，不受已绑定搜索条件限制，需确认后执行。对于已停止分发或已删除的技能，应在解除绑定前说明无法重新绑定的影响。

08异常与边界

用户遇到的情况应有结果
技能名称为空、标识重复或版本号重复明确指出需修正的信息，不创建重复条目、不覆盖已有版本；保留已填写内容。
ZIP 格式不正确、超限或包内容无法形成有效技能说明失败原因，不能发布无效技能。租户可见版本及历史绑定保持不变。文件大小上限沿用现有上传规范。
用户提交绑定或升级前，平台已撤回分发或删除技能以提交时权限重新校验，不建立无权获取的新绑定；说明该技能已不可获取，原有绑定不受此次失败影响。
用户确认升级前，平台又发布了新版不能静默替换用户已确认的目标版本。若需改用新目标，展示更新后的版本信息并重新确认。
发布、分发或保存失败不能显示为成功；保留此前有效状态，提示重试，避免出现平台与租户版本结果不一致。
用户直接访问不属于本租户的技能不能绕过租户权限查看或绑定。已有历史绑定仅允许查看自己绑定版本的内容，不因此获得其他版本访问资格。
平台技能与空间自建技能同名通过来源及技能标识区分，不自动合并、覆盖或替换绑定。
删除仍被 Agent 使用的空间自建技能按既有规则提示先解绑再删除。此规则与平台删除后保留历史绑定的规则分开处理。

以上异常规则是面向真实产品的结果要求。交互原型使用演示数据，不代表已经实现包校验、权限校验或跨租户同步服务。

10待确认事项

唯一未明确的核心规则：停用 Skill 的业务含义。

已确认原型支持超管选择启用 / 停用并同步展示状态，但尚未定义停用是否限制新增绑定、版本升级，以及是否中止已有 Agent 使用。不能把状态展示视为这些规则已确认。

建议方案，待确认：停用后租户列表保留并显示停用，禁止新增绑定及升级；已有 Agent 保持原版本继续可用。重新启用后恢复新增绑定及升级资格，不自动修改已有绑定。

若停用需要承担紧急中止技能执行的职责，则应明确对已有 Agent 的影响及用户提示，另行确认后纳入验收。

除上述状态语义外，本文以已确认原型的用户行为为依据。实现时的包大小限制、技能标识格式、字段长度等继续遵循 Studio 现有规范，不将原型中的演示限制直接扩展为新产品规则。
